面向太阳能小车的**路线—转向—凸轮设计与检验工作台**。目标用户是需要按顺序通过打卡点、使用机械凸轮控制转向的学生与指导者。将原本分散的路线计算、机构运动、轮廓导出和检查连接起来，重点帮助发现设计问题，减少反复试错；目前没有用户对照研究，尚不能量化节省时间或实车成功率。

## 快速体验与状态说明

工具栏点击 **示例与路演**，选择“正常案例”或“问题案例”。两者均来自 `camtool/workbench.py:demo_project()` 的确定性理论输入，页面显示用途、关键参数和来源，不读取或修改用户原始方案；“返回原项目”恢复载入前项目快照、文件关联和未保存状态。示例只在点击后运行，常规启动不自动演示或验收。

顶部始终分别显示 **名义打卡、完整设计、最终 DXF、实车** 四层状态，并提示下一步。修改输入使设计结果、导出关联及候选失效；独立检验页是独立快照，其旧报告不能自动成为新设计的通过结论。最终 DXF 状态只关联本次导出的字节哈希、相同项目与比赛运行区间。独立装配、求解精度和来源仍须在检验页核对。

最短流程：新建/打开 → 设置点位与机构 → 计算 → 同步演示 → 问题定位 → 调整并重算 → 导出 → **检验本次导出** → 核对独立参数与来源 → 开始二次检验。问题行提供实际值、限值、单位、位置、超限影响和调整依据。后台任务支持停止，取消后排队的结果也不采用；搜索候选不会自动替换原方案。

导出在后台先生成完整五文件，再替换目标；写入失败或取消时恢复原文件，覆盖需明确确认。此机制防护普通 I/O 失败，不是断电事务；回滚本身失败时保留备份并提示恢复目录。项目保存原有原子替换保持不变。检验报告保留最终 DXF SHA-256，自动文件名只保留 basename；项目快照和用户填写的来源说明仍包含实际设计数据，公开前需自行核对。

## AI 的真实角色与运行方式

当前 **1.9.0** 将 **检查报告 → 设计改进助手** 改为诊断优先：打开即后台分析当前输入，先解释已确认事实、待验证原因和相关部件，再让用户确认哪些部件可改；不需先猜参数或填写全部上下限。默认范围只用于探索，结构试算还须明确允许安装位置联动；高级参数表保留。实际试算后才生成具体尺寸、前后效果、安装代价与主检查/采样/最终DXF证据。预览不改原案，显式采用可撤销。本地1.9.0独立文件夹包含这轮诊断优先界面；旧程序保留。操作与真实案例见 [设计改进助手](docs/IMPROVEMENT_ASSISTANT.md)。这是确定性数值计算，不是运行时大模型推理。

- **开发阶段**：作者使用 AI 辅助需求分析、编程、算法推导、排错与测试；AI 产出的代码和推导仍需验证，自动测试通过不等于模型正确。
- **运行阶段**：确定性工程计算、局部数值优化、有限预算辅助点搜索、最终 DXF 独立回算；没有调用大模型，没有运行时 API 费用，不把规则或数值搜索称为大模型推理，不宣称算法原创或领先。
- 后续大模型仅考虑需求到结构化草稿、诊断解释等辅助场景，需另行验证收益与成本；工程数值和合格判定由确定性计算负责，不允许外部模型直接放宽约束或宣布可制造。

## 源码安装与部署

Windows本地1.9.0文件夹保留完整结构后双击 SolarCam.exe，无需Python；不要只复制exe，_internal是运行依赖。请将用户项目另存到您选择的目录，不覆盖内置理论案例。构建验证见“新版功能验证记录.md”与“发布验证.json”（本地验收凭证）。源码环境使用已确认的 **Python 3.12（含 Tkinter/Tcl/Tk）**，在仓库目录执行：

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

开发验证另安装 `requirements-dev.txt`。依赖文件固定 NumPy/ezdxf 版本；不需要服务端、模型权重、GPU 或 API 密钥。首次安装需要依赖下载，运行阶段默认离线；受限网络环境需预先准备对应 Python/Windows 的依赖包。未验证另一台干净 Windows、其他操作系统或最低硬件配置；不能把本机启动视为通用部署保证。

输入是项目 JSON、点位 CSV、车辆与机构尺寸、比赛要求；输出是 DXF、运动与轮廓 CSV、检查报告及项目快照。相对手工/分散工具的差异是统一参数、可定位诊断、原案候选对比和最终文件回算，不代表已经证明效率领先。无用户访谈、实车数据或商业收入证据。

评分对应、实际证据、90 秒操作稿与从理论到实物的路径见 [路演与验收说明](docs/HACKATHON_READINESS.md)；本次真实检查记录见 [验收结果](docs/HACKATHON_VALIDATION.md)。

软件版本统一定义在 `camtool/version.py`，可在软件“版本与更新日志”入口查看。项目根目录 `CHANGELOG.md` 记录正式版本；`docs/VERSIONING.md` 规定发布流程。旧项目 JSON 的格式版本与软件版本分别维护。

Windows 本地桌面版，支持三轮车路线计算、两种理想转向机构、盘形凸轮设计、CSV/DXF 导出。解压交付文件夹，双击 **SolarCam.exe**。运行不需要安装 Python、MATLAB，不需要 API 密钥，也不需要联网。

## 第一次使用

1. 打开程序，点击“示例与路演”→“正常案例”，或保留初始演示参数点击“计算设计”。
2. 依次查看“场地与试跑”“凸轮轮廓”“机构运动”“计算曲线”和“检查报告”；“同步演示”同屏观看路线、旋转凸轮和转向机构，统一理论时间轴支持倍率、暂停和拖动。
3. 新建自己的项目，填写实车尺寸、机构尺寸、打卡点和场地设置。打卡点按表格行序访问；CSV 为两列 x,y，可含表头。
4. 点击计算，在“问题定位”点击检查项查看位置、实际值、限值和依据。“本地优化”搜索路线张力和局部切线；原方案保留，在“优化对比”显式选择原方案或候选，没有改善时如实显示。
5. 保存项目。导出时建议选一个新的空目录，输出 DXF、两份 CSV、检查报告及项目快照；点击“检验本次导出”，核对独立参数与来源后开始检验。

尺寸均为毫米。示例尺寸不是 YDI 标准件的已核定尺寸，正式设计前必须测量并替换。当前模型需与实物一致后才可用于制作；软件没有自动读取 STEP 装配。

## 传感器位置和起跑方向怎么填

- **车辆 → 传感器前向距离 X / 左向偏移 Y**：填写车上实测的安装距离，以后轴中点为原点，朝车头为 +X、朝车体左侧为 +Y。例如检测中心在后轴前方 60 mm、车体中线上，填 X=60、Y=0；偏右 20 mm 时 Y=-20。本版 X 必须大于 0。
- **场地 → 传感器场地起点 X/Y**：填写传感器起跑时在场地中的坐标，与打卡点共用场地原点。例如起点为 (410,420)，在这里填 410、420。这组坐标与车上的安装距离是不同的数据。
- **场地 → 车头方向角**：直接输入数字，路线图中向右为 0°、向上为 90°、向左为 180°、向下为 -90°；留空时朝向打卡表格第 2 点。
- **车辆 → 前轮转角上限**：按实车可达到的最大偏转角填写。实际路线转角由计算得到，调大上限不能消除倒行或驱动轮反转。

## 重要约定

- 前面一个小转向轮，后面两个大轮，各自独立旋转；按所选驱动侧计算驱动里程。
- 后轴中点为车体原点，车头 +X、车体左侧 +Y。传感器在后轴前方（X > 0）。
- 车头方向角以场地 +X 为 0°、逆时针为正；留空时朝向第二个打卡点。
- 速度为后轴中点恒定地速。传动比是“驱动轮圈数 / 凸轮圈数”，不是电机减速比。
- 凸轮 +1 为逆时针，-1 为顺时针；相位只改变输出几何的起始朝向，装配时必须对准。
- “设计保底基圆半径 + 中位抬升 + 接触半径”决定中位接触中心到凸轮轴的距离。报告另列实际最小半径和转向轴安装坐标。

## 输出文件

| 文件 | 用途 |
|---|---|
| cam.dxf | 毫米、模型空间 1:1 的封闭轮廓与分层参考线 |
| motion.csv | 驱动/后轴里程、时间、目标转角、从动件位移、凸轮角、回算传感器坐标 |
| cam.csv | 整圈理论/实际轮廓坐标、名义转角和压力角，末点重复首点用于闭合 |
| 检查报告.md | 检查结果、假设、主要指标、安装坐标 |
| project.cam.json | 与导出结果对应的项目快照 |

DXF 的 CAM_OUTLINE 是外轮廓，CENTER_HOLE 是中心孔。BASE_CIRCLE、ROLLER_PATH、STEERING_AXIS 是参考层，加工前关闭。轮廓是离散多段线，应在 CAD 中核对采样精度、闭合、孔径及安装关系。

## 凸轮出发点与旋向

「凸轮轮廓」中的红色 **出发点 S0** 对应驱动里程为 0 时的实际轮廓接触点，已包含设置的起始相位；橙色箭头表示凸轮实体的旋转方向。顺逆时针均以正对软件图 / DXF 这一面观察为准，从另一面观察，视觉上的顺逆时针相反。

装车时打开「机构运动」，将进度条拖到最左，按图中的初始机构姿态，让 S0 对准滚子/球接触位置，再固定凸轮与传动轴。图下方显示起跑前轮角，不能一律将前轮摆直；相位已经计入，不要重复叠加。

保留参考图层时，DXF 含 **START_REFERENCE**（S0 出发点）和 **ROTATION_REFERENCE**（CW 顺时针 / CCW 逆时针）标记；这些图层用于装配参考，加工外形仍使用 CAM_OUTLINE。如需刻印，单独安排标记工序。选择「仅轮廓与孔」时不导出参考标记。检查报告记录出发点坐标、旋向和初始前轮角。

## 计算范围

平推模型是导向滑块—固定长度连杆—转向臂销；顶球模型是转向摆臂上的球心圆弧。它们是可配置的理想平面模型，未自动识别 YDI 的销槽或其他空间结构。若实物运动不符，需先调整模型/实测标定，不能只换一个名称就当作精确装配仿真。

检查覆盖打卡顺序、离散名义转向回算、传感器/轮心场地边界、圆障碍物、转角、整圈行程、压力角、曲率过切、接触干涉及单圈容量。轮宽、外壳包络、弹簧力、间隙、惯性、打滑及制造误差尚未计算，仍须实车低速试跑。

## 独立二次检验

工具栏点“二次检验”，选择最终 `cam.dxf`。可复制当前设计参数作为初值，也可读取项目、保存的检验配置或独立填写实测值。在三个参数页核对车辆、机构、实测装配、来源、起跑姿态和计划运行区间后开始检验。

该系统直接从最终 CAM_OUTLINE 折线反求滚子/球接触和前轮角，再独立积分车辆运动。主程序名义角和可选 CSV 只用于对比。整圈核查机构，只将计划段纳入打卡路线。界面展示路线叠加、逐点偏差、角度曲线、问题位置和三状态判定，可导出含哈希、软件版本、参数快照及已知限制的报告。

参数继承不等于独立测量，需逐组记录数据来源。弹簧力、脱离接触、摩擦、驱动力矩、轮胎打滑、空间包络和实车性能仍为未验证。详细操作和边界见 `docs/VERIFICATION.md`；正式发布的实际验证记录随包交付。
