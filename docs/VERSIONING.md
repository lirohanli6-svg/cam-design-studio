# 版本与发布维护

1. 软件版本只在 `camtool/version.py` 中定义。使用三段版本号：不兼容更改升主版本，兼容新增功能升次版本，兼容修复升修订号。发布日填写实际本地发布日期。
2. 每次发布同步更新根目录 `CHANGELOG.md`，倒序列出新增、改进、修复、验证情况、已知限制。只记录已实现、已执行的事实；历史不明就注明未记录。
3. 窗口标题、设计报告、二次检验报告、交付说明、版本文件与包名读取同一版本模块。项目 JSON 的 schema version 单独维护。
4. 运行相应单元测试、类型检查、界面检查。把命令、实际结果和未覆盖范围写入验证记录。
5. `python build_app.py --package` 构建 `dist/v<版本>/SolarCam`，并生成工作区根目录带版本号的交付文件夹和 ZIP。新交付文件夹已存在时拒绝覆盖，先检查版本及待发布内容；不要覆盖用户项目和旧包。
6. 必须从 ZIP 解压后的新版运行启动、设计计算、二次检验和报告导出。`SolarCam.exe --smoke-dir <新的验证目录>` 可执行这条端到端验证链，检查 smoke.json 与错误文件。
7. 日志里的验证项必须与实际结果一致，不能将几何、动画或采样稳定描述成实车性能保证。
8. 当前 1.4.0 新增兼容的单元格编辑与独立新增操作，由 1.3.0 升次版本；历史记录保留在 `docs/WORKBENCH_VALIDATION_v1.2.0.md` 和 `docs/WORKBENCH_VALIDATION_v1.3.0.md`。Windows EXE 属性读取同一版本来源。本次验证写在 `docs/WORKBENCH_VALIDATION.md`。运行 `tools/release_smoke.py --attach-proof` 检查真正 ZIP 解压的程序并附凭证；附凭证后核对 ZIP 完整性和 EXE 哈希，不修改旧版。

9. 1.5.0 为兼容新增辅助控制、搜索与主端精度复算，由 1.4.0 升次版本。旧 v1.4.0 验证记录归档到 `docs/WORKBENCH_VALIDATION_v1.4.0.md`；本轮验证不得沿用历史结论。候选最终 DXF 检验必须保留实际被检字节和哈希。

10. 嵌入式Python构建先探测匹配的Tcl/Tk数据并检查完整Tk可用性，缺失则拒绝发布；清理PyInstaller缓存。源码界面能运行不能替代ZIP解压EXE验证。保留检查的基线路径缺失必须明确未验证，不能修改旧基线掩盖差异。

11. 1.5.1为必过点回算采样与判定展示的兼容修复，从1.5.0升级修订号。设计点数是请求起始密度，报告必须记录实际使用密度；精度复算比较实际点数，不得按请求点数增加就宣称已加密。

12. 1.6.0 为兼容新增辅助点完整编辑、双列表隔离与地图操作，从1.5.1升级次版本，schema仍为1。归档1.5.1验证记录；发布门禁同时运行原生Tk双列表键盘/地图验收及真实搜索候选的显式采用。新增/调整共用编辑组件时，须同时回归两类点及小窗口，不能仅检查辅助页。

13. 1.7.0 为兼容新增缩放/平移与独立窗口，升级次版本；归档1.6.0验证记录。发布门禁增加主图/放大窗口相机、浏览编辑隔离、真实窗口外鼠标松开、同步播放和拖动性能检查。显示变换不得写入项目坐标或改变导出尺寸。

14. 1.8.0 新增设计改进助手后，显式解压EXE冒烟必须执行实际授权试算、预览、显式采用/撤销、取消/迟到结果隔离、原文件保护及候选实际DXF哈希；普通启动不得运行验收。最终ZIP另存外部SHA256回执，避免把自身哈希写入ZIP造成自引用。

15. 用户只要求文件夹时，使用build_app.py --folder-only，禁止顺带生成ZIP；tools/release_smoke.py --folder-only验证完整独立文件夹副本（可附本地凭证）。记录应明确不是ZIP验证，不在线发布。普通启动不执行验收。
