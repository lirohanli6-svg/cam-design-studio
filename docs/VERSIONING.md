# 版本与发布维护

1. 软件版本只在 `camtool/version.py` 中定义。使用三段版本号：不兼容更改升主版本，兼容新增功能升次版本，兼容修复升修订号。发布日填写实际本地发布日期。
2. 每次发布同步更新根目录 `CHANGELOG.md`，倒序列出新增、改进、修复、验证情况、已知限制。只记录已实现、已执行的事实；历史不明就注明未记录。
3. 窗口标题、设计报告、二次检验报告、交付说明、版本文件与包名读取同一版本模块。项目 JSON 的 schema version 单独维护。
4. 运行相应单元测试、类型检查、界面检查。把命令、实际结果和未覆盖范围写入验证记录。
5. `python build_app.py --package` 构建 `dist/v<版本>/SolarCam`，并生成工作区根目录带版本号的交付文件夹和 ZIP。新交付文件夹已存在时拒绝覆盖，先检查版本及待发布内容；不要覆盖用户项目和旧包。
6. 必须从 ZIP 解压后的新版运行启动、设计计算、二次检验和报告导出。`SolarCam.exe --smoke-dir <新的验证目录>` 可执行这条端到端验证链，检查 smoke.json 与错误文件。
7. 日志里的验证项必须与实际结果一致，不能将几何、动画或采样稳定描述成实车性能保证。
8. 当前 1.3.0 因新增兼容的批量删除操作，由 1.2.0 升次版本；1.2.0 的验证记录保留在 `docs/WORKBENCH_VALIDATION_v1.2.0.md`。Windows EXE 属性由打包脚本从同一版本模块生成。本次验证写在 `docs/WORKBENCH_VALIDATION.md`。运行 `tools/release_smoke.py --attach-proof` 检查真正的 ZIP 解压程序并附执行凭证；附凭证后再次校验 ZIP 完整性和 EXE 哈希，不修改旧版。
